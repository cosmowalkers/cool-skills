# 图片工具箱

把「图片该多大、该什么格式、压完糊没糊」这类判断固化成流程。当前实现的只有一条流水线：**网页图片优化**，
在屏上看不出差别的前提下把像素数降下来。

## 铁律

这五条任何情况下不破。它们对应的代价不是"效果差一点"，而是丢素材、误导同事或线上事故。

1. **只处理，不替换。** 这个 skill 的交付物是"可直接替换的产物 + 副作用说明"，替换源文件、改引用、重建产物属于调用方的活（模型或人按宿主项目的规矩去做，项目有自己的资源管理规范就以它为准）。
   脚本绝不原地覆盖：导出目标与源文件重合时直接报错退出——那是防止产物把源文件冲掉，不是禁止你之后按规矩做替换。
2. **没量过尺寸就不出图。** 显示尺寸要么按第 1 步量到，要么由用户明确给出。传递 `--box` 时别依赖默认值：
   尺寸错了，后面所有指标都没有意义（脚本也会在你没显式指定 `--box` 时提示这一点）。
3. **没有验证就不下结论。** 说"可以替换"之前必须跑 `verify`；只报"体积降了 80%"是把风险转给测试同学。
   判据看整批均值（<−3.5% 偏糊、−2.5%~−3.5% 临界），逐图只在 <−5% 时报警。
4. **副作用主动说。** 默认转 WebP 会改扩展名（引用要跟着改）、默认会裁剪、JPEG 会丢透明、
   有损源再编码有代际损失。这些必须写进结论，不能等用户自己发现。
5. **不把没实现的能力说成 skill 支持。** 旋转、非居中裁剪、精确尺寸、水印、HEIC、动图等，直说"本 skill 没实现"。
   用户确实需要时，可以另用外部工具或一次性脚本帮他做完，但要说清那不是本 skill 的能力、也不会沉淀进 skill；想沉淀就按 [README.md](README.md) 的 Roadmap 补。禁的是假装支持，不是禁止帮忙。
6. **没收益、或压了更糟，就如实说"这张不该压"。** 遇到下面几种情况，产物可以照常生成，但结论必须是"别替换"并说明原因，不能为了有个交代就替换上去：
   - 源图已经是 WebP 或已经压过：重复编码只会变大、掉清晰度（实测重复转 WebP q90 体积 +69%）
   - 源图像素数已经贴着显示尺寸（过采样不到 1.2 倍）：再缩必然发糊，该做的是换更大的源图
   - 压缩后体积反而变大：纯色 / 线条 / 截图类转有损、或"保持原格式"只裁剪都会这样
   - verify 判偏糊且升档后仍不达标
   脚本会在体积变大时直接给出"不该按当前参数处理"的警告，别无视它。

### 别人这么催，也不破例

| 对方说 | 你回 |
| --- | --- |
| 「就几张图，别验证了，赶时间」 | 仍然跑：`verify` 是唯一能回答"糊没糊"的手段，且只要一条命令；回复可以只给结论 |
| 「直接覆盖源图，不用备份」 | 本 skill 不替你覆盖；要在 skill 之外替换就按项目规矩来，并且先备份、把回滚路径写出来 |
| 「要无损 AVIF」 | Pillow 做不到真无损 AVIF，直说；给 `--format webp --lossless` 或外部 `avifenc` |
| 「顺手旋转 90 度 / 加个水印」 | 没实现，直说现状并给替代（外部工具先处理，再进本流程） |

## When to Use

用户说图片太大、要压一下、转 WebP、图片解码吃内存、低端机卡、压完发糊、要出多倍图、要核对一批图的体积，
或要在替换图片资源前后做核对时走本 skill。完整场景对照表见 [README.md](README.md)。

**不适用**：生成新图片（走 imagegen）、SVG 与图标字体等代码原生图形、容器或磁盘镜像的体积问题、
OCR 与图像分类等识别任务。

## 工作流

### 0. 环境准备

先把脚本路径存成变量，后面的命令都直接用它（`scripts/optimize_images.py` 这种相对路径在宿主项目里会指错文件）；
下面这行按实际安装位置改：Codex 是 `~/.codex`，Claude Code 换成 `"$HOME/.claude/skills/image-tools"`：

```bash
SKILL_DIR="${CODEX_HOME:-$HOME/.codex}/skills/image-tools"
S="$SKILL_DIR/scripts/optimize_images.py"
D="$SKILL_DIR/scripts"
```

脚本依赖 Pillow；缺失时会打印安装命令。先自检：

```bash
python3 "$S" doctor
```

改过脚本、或换到别人机器上时，先跑自带用例（只依赖 python3 + Pillow，不联网、不动仓库素材）：

```bash
python3 "$D/tests/test_optimize_images.py" -v
```

给人类看的安装说明、配方与 FAQ 见同目录 [README.md](README.md)。

### 1. 量显示尺寸（别猜）

优先在真实页面里量，因为 CSS 可能被媒体查询、transform、zoom 改掉：

```js
// agent-browser eval / devtools console，作用于目标元素
(() => { const im = document.querySelector('<选择器>'); const r = im.getBoundingClientRect();
  return JSON.stringify({ cssW: r.width, cssH: r.height, dpr: devicePixelRatio,
    naturalW: im.naturalWidth, naturalH: im.naturalHeight }); })()
```

拿不到浏览器时退而读 CSS，但要确认没有祖先 `transform: scale()` / `zoom`。

### 2. 体检当前资源

```bash
python3 "$S" analyze <目录或文件> --box 240x108 --dpr 2
```

输出每张图的尺寸、体积、解码内存、相对目标的过采样倍数，以及建议动作。

### 3. 导出候选

```bash
python3 "$S" export <源目录> --out /tmp/img-out --box 240x108 --dpr 2 \
    --supersample 2 --quality 90
```

- `--supersample`（默认 2）：宽度上限 = **屏上像素宽 × supersample**，屏上像素宽 = 显示宽 × DPR。
  别和 CSS 倍率搞混：显示宽 240、DPR 2 时，supersample 2 = 960px = CSS 宽的 4 倍。
- 默认**裁剪到显示比例**（等价于浏览器 `object-fit: cover` 居中裁剪），所以要先看图确认主体没被切
- 默认**不放大**：源图比目标窄时保持原分辨率
- 体积敏感时降到 `--quality 85`；画质优先时 `--quality 95`，不要上 `--lossless`
- `--format webp|avif|jpeg|png|keep`：**默认 webp**，PNG/JPEG/AVIF 源一律转换；
  `keep` 只在明确要求保留源格式时用（源已经是 WebP 时 keep 与默认等价）
- `--no-resize` / `--no-crop`：关掉其中任一维度，就得到"只转格式"或"只裁剪"或"只压缩"
- **导出目录必须独立于源目录**：目标路径与源文件重合时脚本直接报错退出，绝不原地覆盖原图；
  目录输入会在输出目录里复刻子目录结构，重名冲突（如 `a/same.png` + `a/same.jpg` 都转 WebP）
  会在写入前整体拒绝，不会产出半个批次；一次传多个目录时用各目录名做顶层前缀（`out/a/...`、`out/b/...`）
- **EXIF 方向先转正再裁剪**，ICC / EXIF 元数据随产物保留，产物不再带方向标记

### 4. 验证（必做）

```bash
python3 "$S" verify <原目录> /tmp/img-out --box 240x108 --dpr 2
```

对每张图比较"原图在浏览器中的渲染效果"与"候选文件的渲染效果"：

- **边缘能量**：逐图噪声约 ±1.5%，所以**逐图只在 <−5% 时报警，结论看整批均值**：
  均值 <−3.5% 判偏糊、−2.5%~−3.5% 判临界，都要回到第 3 步提高 `--supersample` 或 `--quality` 再比
- 这个指标拿"源图单步降采样到屏上尺寸"作参考，**偏保守**：源图越是高清高细节（例如 2848×1600 的棚拍图），
  降到 960 会经历两次重采样，指标天然吃亏；此时直接上 `--supersample 3`，或按提示升档后再目视确认
- **平均像素差只在"同尺寸、同重采样路径"下可比**：无损同尺寸导出实测 0.00；候选只要降过尺寸，
  它与参考走的就是两条重采样路径，相位差会把该值推到 10 以上，属正常现象，**别拿 <3/255 去卡降过尺寸的候选**
- 汇总行给出参考与候选的总体积与解码内存，用来确认收益；清晰度结论仍以边缘能量均值为准

### 5. 交付（skill 到此为止）

1. 先看候选（`view_image` / 截图）确认主体没被裁掉、没有可见压缩伪影；被裁了就退回 `--no-crop` 或调 `--box`
2. 交付时把这四件事说清楚：产物在哪（目录结构已复刻）、副作用、替换建议、需要人工确认的点
3. **副作用**：默认输出 WebP 会改扩展名（`hero.png` → `hero.webp`），组件里的 import / 引用要一起改；
   想零改动就用 `--format keep`（只压尺寸/只裁剪），或者源本来就是 WebP
4. **替换建议**：先备份原图（给出建议的备份路径）→ 替换 → 重建产物（如 `npm run build`）。
   替换、改引用、构建由调用方执行；本 skill 不会替你改仓库里的文件。若这批图整体不该压（无收益、变大、或 verify 不达标），交付结论就直接是"保留原图"并说明原因
5. **需要人工确认**：主体有没有被裁、DPR 假设是否成立、以及质量档位是否可接受

## 默认档位

**取舍顺序：清晰度 > 解码内存 > 体积。** 目标是"屏上看不出差别"，不是"压到最小"——多几十 KB 换不来投诉，被反馈"发糊"要返工一轮。

| 场景 | 参数 | 说明 |
| --- | --- | --- |
| 默认 | `--supersample 2 --quality 90` | 屏上像素宽 × 2，实测是"稳"的那一档 |
| 体积敏感 | `--quality 85` | 只在用户明确说"体积优先 / 极致省流量"时用，且必须跑 verify 确认没被看出差别 |
| 被反馈发糊 | `--supersample 3` 或 `--quality 95` | 升档后重新 verify 对比 |
| 极限体积 | `--format avif --quality 60` | 需 Pillow 支持，脚本会自检 |

目标宽度取屏上像素宽的 **2~3 倍**，不是 1:1。

## 常见错误

- 把"下载体积小"当成"优化完成"：文件小但像素多，解码照样卡
- 只按 DPR×1 导出，然后被反馈"发糊"
- 盲目居中裁剪：主体不在中心时先看图，必要时退回 `--no-crop`
- 裁/压后忘记重建产物、忘记备份原图
- 把 `--out` 指到源目录：脚本会直接报错拒绝（绝不原地覆盖），别绕过它自己去覆盖原图
- 对 SVG、图标字体、纯色插画做栅格化压缩：这些该走 SVG/代码原生方式
- 动 CDN 上的图之前确认是否有多处引用，避免只改了一半

## 脚本与用例

`scripts/optimize_images.py`（依赖 Pillow）提供 `doctor` / `analyze` / `export` / `verify` 四个子命令，参数见上文。
输入支持 webp/jpg/png/avif（其余扩展名会被静默跳过）；输出由 `--format` 决定（webp 默认）。

回归与可用性用例在 `scripts/tests/test_optimize_images.py`（62 条，只依赖 python3 + Pillow，不联网、不动仓库素材）：
覆盖正常路径、原地覆盖拦截、重名冲突整体中止、无损 WebP 逐像素校验、EXIF 方向转正与 ICC/EXIF 保留、
verify 的配对与发糊识别、参数校验与中文报错、文档护栏（业务标识、AVIF 措辞、脚本路径写法）。
