# 多仓共性分析

当 prompt 要求从多个仓库识别共性、沉淀到 common 或生成共享知识时，先分别完成每个仓库的
Discovery，再运行确定性对比，最后由 AI 根据证据做归因。

对比结果必须区分：

- `common_candidate`：两个或以上仓库表达相同约束、流程或决策，且证据指向 common 可承载的能力；
- `similar_but_different`：名称或结构相似，但语义、边界或实现不同，不能直接合并；
- `repository_only`：只在单仓出现，保留在对应仓库；
- `code_projection`：只是目录、组件、路由或类型事实，不生成知识页。

每条共性候选必须保留证据矩阵：

| 候选 | 仓库 | 证据 | 结论 |
|---|---|---|---|
| 统一请求错误处理 | mall-ui | `src/...` | 待确认共性 |
| 统一请求错误处理 | console-ui | `src/...` | 待确认共性 |

只有在人工确认后，才生成 common 页面。主仓页面应引用 common 页面，并只记录本仓差异、
覆盖关系或使用边界。抽取后必须检查：common 页面没有依赖单仓命名，仓库差异没有重复
common 正文，也没有因抽取丢失仓库特有约束。
