# 页面更新策略

“更新”指一次变更对账，不限定动作是新增、修改、删除还是迁移。先根据代码变更和
页面正文中的验证来源计算影响范围，再决定最终动作；没有命中的页面不能默认删除或
重写。

| 目录 | 更新方式 | 规则 |
|---|---|---|
| `guide/` | 原地更新 | 步骤、脚本或依赖变化时更新 |
| `rules/` | 原地更新 | 代码或 lint 配置直接证明的规则可对账更新；新增推断规则必须人工确认 |
| `reference/` | 原地更新 | 事实变化时更新验证来源和正文 |
| `gotchas/` | 视根因更新 | 同一根因补充原页；不同根因新建页面 |
| `decisions/` | 按独立主题追加，不覆盖 | 一个独立决策一个页面；新主题新建页面，原决策改变时新建新决策页，旧页追加替代说明 |

## 变更动作

- `create`：新增当前知识库没有覆盖的知识；
- `update`：已有页面的证据、步骤、边界或验证方式发生变化；
- `delete`：代码和配置明确移除页面事实，且没有替代页面；
- `move`：页面归类、归属或文件名改变；
- `link_shared_page`：事实应回到 common 维护，主仓保留相对路径和本仓差异；
- `remove_repository_difference`：主仓差异已消失；
- `ignore`：代码变更不会改变知识结论。

## 决策页面变更

旧页面保留原文，只允许追加：

```markdown
> 本决策已被 [新决策](./new-decision.md) 替代。
```

不得为了“保持最新”直接重写历史决策，否则会丢失当时的约束、备选方案和权衡过程。

## 共享页面与仓库页面同步

1. 共享规则改变时，先更新共享页面；
2. 检查用户指定范围内的仓库链接是否仍然有效；
3. 只有仓库行为不同，才更新仓库差异页；
4. 仓库差异消失时，执行 `remove_repository_difference`，删除差异正文并保留删除动作的日志；
5. 禁止把共享正文复制到仓库页面形成第二份事实来源。

页面证据暂时无法读取时标记 `stale_evidence`，不要把子模块未初始化、gitlink 未同步或
本地路径变化误判为知识删除。
