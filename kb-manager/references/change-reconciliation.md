# 变更对账

知识库更新的目标是让最终 docs 状态与当前代码、配置、仓库关系和用户明确约束一致。
一次对账可能同时包含新增、修改、删除、迁移和保持不变，不能把“增量”当成动作名称。

## 输入

优先使用以下输入之一：

```bash
git -C <repository> diff --name-status --find-renames <base>..<head>
```

- commit range；
- `git diff --name-status` 输出；
- 用户指定的文件或目录；
- 没有变更范围时，执行一次全量对账。

先运行 `scripts/impact-plan.py`。它从页面正文的 `## 验证来源`、`## 证据`、反引号代码
路径和 Markdown 链接中提取代码路径，生成受影响页面、未映射变更和候选动作。未映射
变更必须进入 Discovery，不能因为没有命中旧页面就忽略。

## 动作

| 动作 | 使用条件 | 处理要求 |
|---|---|---|
| `create` | 当前代码形成了已有页面未覆盖的可沉淀知识 | 先查重，再写页面并加入 README |
| `update` | 现有页面的证据发生变化 | 同步正文、验证来源和关联 |
| `delete` | 页面事实由代码删除或用户明确要求删除 | 同步移除 README 条目并追加 log |
| `move` | 页面分类、归属或文件名改变 | 先更新链接，再删除旧路径 |
| `link_shared_page` | 内容应回到 common 维护 | 主仓只保留相对路径和本仓差异 |
| `remove_repository_difference` | 主仓差异已消失 | 删除差异正文，保留同名入口或按组织规则改为引用 |
| `ignore` | 变更只是代码投影、格式变化或不形成知识 | 在任务记录中保留原因 |

## 删除边界

- 代码明确删除了页面对应功能，并且页面正文中的验证来源全部失效时，可以生成 `delete` 计划；
- 仅因为证据路径暂时不存在、子模块未初始化或 common gitlink 未同步时，只能标记
  `stale_evidence`，不能删除；
- `decisions/` 不删除历史页面；新事实用新决策页，旧页追加替代说明；
- 删除实质内容时，任务中必须记录失效证据、受影响链接和替代页面。

## 最小执行路径

普通代码变更只需：

```text
读取变更 → impact-plan.py → 更新受影响页面 → 同步索引和日志 → verify-doc
```

只有命中规则、决策、组织归属、common 抽取或无证据删除时，才增加人工确认。

## 证据要求

新建或变更页面在正文的 `## 验证来源` 或 `## 证据` 中使用仓库相对路径。跨仓共享
页面使用 `仓库标识:仓库相对路径`，例如 `mall-ui:nuxt.config.ts`；单仓页面不加仓库
前缀。路径应指向代码、配置、测试或脚本，不要只写目录名。正文可以提炼代码无法直接
读取的流程和边界，但不能把路径列表本身当成知识内容。
