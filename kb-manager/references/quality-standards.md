# 知识页面质量标准

质量评价分为硬性检查和五个维度。硬性检查不通过时，页面不能标记为合格。

## 硬性检查

- 页面从 Markdown 标题和摘要开始，不包含 YAML frontmatter；
- 页面有摘要、正文和适用范围；
- `README.md` 有对应索引条目；
- 页面中的本地 Markdown 链接都存在；
- 页面至少有一个有效关联；
- 代码来源和验证路径写在正文，并且能回到当前代码；
- 共享页面和仓库差异页面符合用户确认的组织方案；
- `decisions/` 的历史页面没有被原地重写；
- 没有把同一条知识复制到多个页面作为独立事实来源；
- 没有明显的占位内容、猜测性结论或空泛建议。

## 五个评价维度

每项 0–20 分，总分 100 分，建议 70 分为通过线。

| 维度 | 判断标准 |
|---|---|
| 准确性 | 结论有代码、MR、commit 或正式文档等来源支撑 |
| 实用性 | 能帮助 Agent 做决策、执行操作或规避问题 |
| 完整性 | 交代了结论、边界、原因和影响 |
| 非冗余 | 没有复述代码、官方文档或已有知识页面 |
| 可维护性 | 分类正确、页面原子化、正文验证来源清晰 |

## 一票否决

出现以下任一情况，直接不通过：

1. 关键结论无来源且使用确定语气；
2. 仓库差异页复制了共享页面或其他仓库的完整正文；
3. `decisions/` 覆盖了原历史决策；
4. 页面无法通过索引或链接校验；
5. 页面只描述代码结构，没有任何代码无法直接读出的信息。

## 修复建议格式

```text
页面: docs/...
总分: 62
不通过维度: 准确性、非冗余
问题: ...
建议: 删除代码投影段，补充正文验证来源；如果没有来源，降低确定性并标记待确认。
```

格式问题可自动修复。涉及业务规则、架构决策、仓库组织或删除实质内容时，必须先让
用户确认。代码事实页面可以在证据明确时直接修复。
