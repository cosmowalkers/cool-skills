# docs 页面格式规范

知识页不使用 YAML frontmatter，也不在页面顶部生成状态、置信度、负责人或验证日期等
元数据。页面以 Markdown 标题和摘要开始；代码来源、验证路径和适用边界写入正文。
`README.md` 只负责索引，`log.md` 只负责追加变更记录。

## 页面结构

```markdown
# 页面标题

> 2–3 句摘要：说明结论、适用范围和何时阅读。

## 内容

...

## 验证来源

- 代码来源：`src/...`
- 配置或测试：`package.json`

## 适用范围

...

## 关联

- [相关页面](./related.md)
```

页面类型由所在目录确定，不在正文中重复生成 `type` 元数据。
验证来源必须是可定位的仓库相对路径；`code-scan`、`扫描结果`、`跨仓扫描`、
`skill-catalog` 等过程词不能替代路径。

### guide

```markdown
## 前置条件
## 步骤
## 验证
## 常见问题
## 验证来源
## 关联
```

### rules

```markdown
## 规则
## 适用范围
## 例外和边界
## 违反后的影响
## 验证来源
## 关联
```

### reference

```markdown
## 结论
## 适用范围
## 重要字段或约定
## 验证来源
## 关联
```

### decisions

```markdown
## 状态
## 背景
## 决策
## 备选方案
## 权衡与后果
## 验证来源
## 关联
```

`decisions/` 下每个文件只记录一个独立决策主题，目录可以有多个文件。若证据只有
当前代码，应在“状态”或“背景”中说明这是当前实现边界，不得把代码投影改写成历史
决策过程；没有正式来源时不要捏造备选方案。

### gotchas

```markdown
## 症状
## 根因
## 解决
## 预防
## 验证来源
## 关联
```

## 共享页面和仓库差异页

只有用户在 prompt 中要求“共享页面 + 仓库差异”时，才生成共享页和同名主仓入口。
共享页写完整规则。仓库差异页面只写差异，并链接共享页面：

```markdown
## 共享规则

- ...

## 本仓差异

- ...
```

没有差异时，不创建空的差异页。页面建议控制在 80–250 行，超过 400 行按 H2
拆分。页面必须至少关联一个真实存在的相关页面，链接由校验脚本验证。无法提供代码
证据的规则或决策必须在正文中明确说明来源和事实边界，不得用确定语气补全推测。
