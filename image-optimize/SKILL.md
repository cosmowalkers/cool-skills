# 网页图片优化

目标只有一个：**在屏上看不出差别的前提下，把像素数降下来**。体积（下载）和解码内存是两件事，后者在低端机更致命。

**默认输出格式是 WebP**：源是 PNG/JPEG/AVIF 时导出会一律转成 WebP（`--format webp` 是默认值）；
保留原格式属于例外，要显式写 `--format keep`。

## 四条非显然结论（先记住，能省一轮返工）

1. **1:1 导出常常比大图更"糊"。** 浏览器把大图渲染到比自身小的尺寸时会做高质量降采样，等于超采样抗锯齿；只给到 1:1 它就只剩放大插值。实测：把 2848×1600 的图压成 480×216 q80 后，边缘能量（高频细节）掉 5.7%，肉眼可辨；保留 3 倍超采样再让浏览器降采样，只掉 1.4%。
2. **目标不是 DPR 像素，而是它的 2–3 倍（按宽度算）。** 显示 240×108、DPR 2 时，屏上像素宽是 480，480 只是"够用"，960 才稳。
3. **解码内存 = 像素数 × 4 字节，跟文件体积无关。** 2848×1600 一张就是 17.4 MB 解码内存（六张同尺寸就是 104 MB）；q80 压成 480×216 后每张 0.4 MB。真正拖慢低端机的是这个，不是下载量。
4. **有损源图再"无损编码"不会更清晰**，只是保持原样，体积通常是 q95 的 4–5 倍。除非法务/二次编辑有要求，否则别用无损。

## 工作流

### 0. 环境准备

先把脚本路径存成变量，后面的命令都直接用它（`scripts/optimize_images.py` 这种相对路径在宿主项目里会指错文件）；
下面这行按实际安装位置改：Codex 是 `~/.codex`，Claude Code 换成 `"$HOME/.claude/skills/image-optimize"`：

```bash
SKILL_DIR="${CODEX_HOME:-$HOME/.codex}/skills/image-optimize"
S="$SKILL_DIR/scripts/optimize_images.py"
D="$SKILL_DIR/scripts"
```

脚本依赖 Pillow；缺失时脚本会直接打印安装命令（不会甩 traceback），也可以先自检：

```bash
python3 "$S" doctor
```

改过脚本、或换到别人机器上时，先跑一遍自带用例（只依赖 python3 + Pillow，不联网、不动仓库素材）：

```bash
python3 "$D/tests/test_optimize_images.py" -v
```

给人类（前端研发）看的上手文档、配方与 FAQ 见同目录 [README.md](README.md)；本文件是给 Codex 的操作口径，
两者不重复：判断标准与阈值以本文件为准，安装与日常用法看 README。

### 1. 量显示尺寸（别猜）

优先在真实页面里量，因为 CSS 可能被媒体查询、transform、zoom 改掉：

```js
// agent-browser eval / devtools console，作用于目标元素
(() => { const im = document.querySelector('<选择器>'); const r = im.getBoundingClientRect();
  return JSON.stringify({ cssW: r.width, cssH: r.height, dpr: devicePixelRatio,
    naturalW: im.naturalWidth, naturalH: im.naturalHeight }); })()
```

拿不到浏览器时退而读 CSS，但要确认没有祖先 `transform: scale()` / `zoom`。

### 2. 体检当前资源

```bash
python3 "$S" analyze <目录或文件> --box 240x108 --dpr 2
```

输出每张图的尺寸、体积、解码内存、相对目标的过采样倍数，以及建议动作。

### 3. 导出候选

```bash
python3 "$S" export <源目录> --out /tmp/img-out --box 240x108 --dpr 2 \
    --supersample 2 --quality 90
```

- `--supersample`（默认 2）：宽度上限 = **屏上像素宽 × supersample**，屏上像素宽 = 显示宽 × DPR。
  别和 CSS 倍率搞混：显示宽 240、DPR 2 时，supersample 2 = 960px = CSS 宽的 4 倍。
- 默认**裁剪到显示比例**（等价于浏览器 `object-fit: cover` 居中裁剪），所以要先看图确认主体没被切
- 默认**不放大**：源图比目标窄时保持原分辨率
- 体积敏感时降到 `--quality 85`；画质优先时 `--quality 95`，不要上 `--lossless`
- `--format webp|avif|jpeg|png|keep`：**默认就是 webp**，PNG/JPEG/AVIF 源一律转换；
  `keep` 只在明确要求保留源格式时用（源已经是 WebP 时 keep 与默认等价）
- `--no-resize` / `--no-crop`：关掉其中任一维度，就得到"只转格式"或"只裁剪"或"只压缩"
- **导出目录必须独立于源目录**：目标路径与源文件重合时脚本直接报错退出，绝不原地覆盖原图；
  目录输入会在输出目录里复刻子目录结构，重名冲突（如 `a/same.png` + `a/same.jpg` 都转 WebP）
  会在写入前整体拒绝，不会产出半个批次；一次传多个目录时用各目录名做顶层前缀（`out/a/...`、`out/b/...`）
- **EXIF 方向先转正再裁剪**，ICC / EXIF 元数据随产物保留，产物不再带方向标记

### 4. 验证（必做）

```bash
python3 "$S" verify <原目录> /tmp/img-out --box 240x108 --dpr 2
```

对每张图比较"原图在浏览器中的渲染效果"与"候选文件的渲染效果"：

- **边缘能量**：阈值按真实反馈校准过——被用户判"发糊"的档位整批均值 −4.0%（480 宽 + q80），
  用户认可的档位（960 / 1440 宽 + q90）均值在 −1.2% ~ −1.7%。逐图噪声约 ±1.5%，
  所以**逐图只在 <−5% 时报警，结论看整批均值**：均值 <−3.5% 判偏糊、−2.5%~−3.5% 判临界，都要回到第 3 步提高
  `--supersample` 或 `--quality` 再比
- 这个指标是拿"源图单步降采样到屏上尺寸"的理想结果作参考，**偏保守**：源图越是高清高细节
  （例如 2848×1600 的棚拍图），降到 960 会经历两次重采样，指标天然吃亏。此时直接上 `--supersample 3`，
  或按指标提示升档后再用真实浏览器截图目视确认
- **平均像素差**：<3/255 属正常编码噪声
- 同时打印两边的体积与解码内存，确认收益

### 5. 落地

1. 先看候选（`view_image` / 截图）确认主体没被裁掉、没有可见压缩伪影；被裁了就退回 `--no-crop` 或调 `--box`
2. 替换前把原图复制到临时目录备份，并在回复里说明备份路径（脚本不会替你动源文件）
3. 替换：输出目录复刻了源目录结构，可以整目录覆盖，例如 `cp -R /tmp/img-out/. <源目录>/`
4. **注意扩展名变化**：默认输出 WebP，`hero.png` 会变成 `hero.webp`，组件里的 import/引用要一起改；
   想零改动就用 `--format keep`（只压尺寸/只裁剪），或者源本来就是 WebP
5. 替换后重建产物（如 `npm run build`），确认产物里的哈希与体积已更新

## 档位参考

实测环境：显示 240×108、DPR 2（屏上 480×216），素材是一组照片型图片（其中一张 2848×1600，六张合计约 60 MB 解码内存）。"边缘能量"是与
"原图在浏览器里的渲染效果"比，下降越多越可能被说发糊。

| 导出 | supersample | 单张体积 | 六张合计 | 解码内存/张 | 边缘能量 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| 480×216 q90 | 1 | 11.5 KB | 80 KB | 0.4 MB | 96.6%（−3.4%） | 偏省，接近可感知 |
| **960×432 q90** | **2** | **37 KB** | **208 KB** | **1.6 MB** | **98.0%（−2.0%）** | **推荐默认** |
| 1440×648 q90 | 3 | 72 KB | 316 KB | 3.7 MB | 98.0%（−2.0%） | 边际收益已趋零 |
| 原分辨率 2848×1282 q95 | 6 | 255 KB | 710 KB | 13.9 MB | ≈100% | 只在极限需求时 |
| 原分辨率 2848×1282 无损 | 6 | 1079 KB | 3.2 MB | 13.9 MB | 100% | 基本不值得 |

同一档位下 `--quality` 也影响观感：480 宽在 q80 时边缘能量只有 94.3%，换 q90 就到 96.6%。

## 转格式、压尺寸、裁剪是三个独立维度

**默认输出格式是 WebP**：源是 PNG/JPEG/AVIF 时一律转过去，`--format keep` 只在明确要求保留原格式时才用
（脚本遇到 keep 会打印提醒）。三个维度可以任意组合，也可以只做其中一件。实测数据来自真实照片型素材：

| 目标 | 命令 | 实测结果 |
| --- | --- | --- |
| 只转 WebP（不动尺寸、不裁剪） | `--no-crop --no-resize --quality 90` | JPEG 1208 KB → **259.8 KB（−78%）**；PNG 11.1 MB → 660 KB（−94%），尺寸与解码内存不变 |
| 只转 WebP 且零损失 | 同上换 `--lossless` | PNG 11.1 MB → 无损 WebP 8.5 MB（−24%），像素完全一致 |
| **压尺寸 + 转 WebP**（不裁剪） | `--no-crop --max-width 960` | JPEG 1208 KB → **42.5 KB（−96%）**，解码 17.4 MB → 2.0 MB |
| **压尺寸 + 裁剪 + 转 WebP**（默认组合） | 不加参数，或给 `--box/--dpr` | JPEG 1208 KB → **40.3 KB（−97%）**，解码 17.4 MB → 1.6 MB；六张 WebP 341 KB → 195 KB |
| 转 AVIF | `--format avif --quality 60` | JPEG 1.2 MB → 112.8 KB（−91%）；需 Pillow 支持，脚本会自检 |
| 例外：保留原格式压缩尺寸 | `--format keep --no-crop --max-width 960` | 六张 341 KB → 208 KB（仅当你明确要不转格式） |
| 例外：保留原格式与分辨率只裁剪 | `--format keep --no-resize --box 240x108` | 六张 341 KB → **510 KB（反而变大）**，解码 59.9 MB → 46.1 MB |

**别踩的三个坑**：

1. **只裁剪通常得不偿失**：保持原分辨率裁剪，体积会因为重新编码变大（实测 +49%），解码内存也只降 23%——裁剪的价值在于"配合降到合理尺寸"，不是单独用。
2. **转格式不等于变小**：纯色、线条、截图类内容转 JPEG 会变大（实测 1.4 KB → 21 KB）；照片类转 WebP/AVIF 才收益明显。已经是 WebP 的图再"转 WebP"没有意义，只调尺寸/质量即可。
3. **只转格式不降解码内存**：解码内存只跟像素数有关（`像素 × 4 字节`），换容器格式不会变。想省内存必须降尺寸。

其他约束：

- **明示转其他格式**：`--format avif|jpeg|png|keep`；默认 webp，只有明确要求才写别的
- **无损**：只有 webp 与 png 能真无损。`--format webp --lossless` 实测逐像素一致（最大像素差 0）；
  **Pillow 的 AVIF 编码器不支持无损**（它没有 lossless 开关，传了会被静默忽略并回落到 q75），
  所以 `--format avif --lossless` 会被脚本直接拒绝，提示改用 `--format webp --lossless` 或外部 `avifenc`；
  jpeg 不支持无损，传了会被忽略并提示；png 本身无损（`optimize + compress_level 9`，`--quality` 不生效）
- **别把照片转 PNG**：连续色调下 PNG 反而暴涨（实测 109 KB → 1.6 MB），PNG 只用于需要无损/透明的素材
- 有损源（JPEG/有损 WebP）再编码会有**代际损失**；能零损失就零损失（截图/线条图 → 无损 WebP；确需无损 AVIF 走外部 `avifenc`）
- **透明通道**：webp / avif / png 都保留 alpha；jpeg 不支持，脚本按 `--flatten-color`（默认黑）合成底色并打印提示

## 常见坑

- 把"下载体积小"当成"优化完成"：文件小但像素多，解码照样卡
- 只按 DPR×1 导出，然后被反馈"发糊"
- 盲目居中裁剪：主体不在中心时先看图，必要时改裁剪位置或退回 `--no-crop`
- 裁/压后忘记重建产物、忘记备份原图
- 把 `--out` 指到源目录：脚本会直接报错拒绝（绝不原地覆盖），别绕过它自己去覆盖原图
- 对 SVG、图标字体、纯色插画做栅格化压缩：这些该走 SVG/代码原生方式
- 动 CDN 上的图之前确认是否有多处引用，避免只改了一半

## 脚本

`scripts/optimize_images.py`（依赖 Pillow）提供 `analyze` / `export` / `verify` 三个子命令，参数见上文。
输入支持 webp/jpg/png/avif；输出由 `--format` 决定（webp 默认，可选 avif/jpeg/png，或 `keep` 保持源格式）。

EXIF 方向转正与 ICC/EXIF 保留、verify 的配对与发糊识别、参数校验与中文报错。
改脚本后先跑：`python3 "$D/tests/test_optimize_images.py" -v`。
